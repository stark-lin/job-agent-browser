# Current Runtime Architecture

Purpose: record verified runtime behavior. Status: **Implemented** React composition, mixed navigation, Settings, Profile editing/PDF import, Job Capture/Application Agents, Ask AI V2 and Resume Agent V1 with HTML/PDF. Interview Prep remains **Scaffolded**; additional product workflows remain **Planned**.

Language: English · [简体中文](architecture.zh-CN.md)

## 1. Runtime and process boundaries

[Build configuration](../electron.vite.config.ts) selects [Main](../src/platform/electron/main/index.ts), [Preload](../src/platform/electron/preload/index.ts), and the [Renderer HTML entry](../src/renderer/index.html). The [package entry](../package.json) remains `out/main/index.js`.

```text
React App → Page → Preload → IPC → Main
                                  ├── Mixed history + WebContentsView → Session
                                  ├── Domain services → SQLite + audit
                                  ├── AI service → Provider SSE
                                  └── MCP Client → stdio Server → ToolScope → audited capability → Domain
```

The [Renderer bootstrap](../src/renderer/main.tsx) mounts the single [App](../src/app/App.tsx) in StrictMode. [Providers](../src/app/providers.tsx) inject controlled browser/data/AI bridges and context; the [navigation store](../src/app/navigation/navigationStore.ts) subscribes once per provider lifecycle and ignores older snapshots and disposed initialization reads. [Router](../src/app/router.tsx) selects React pages from Main's active destination without navigating the trusted document.

[BrowserPage](../src/pages/browser/BrowserPage.tsx) alone renders tabs, address input and browser controls. Home and business pages render no browser chrome or internal URL. [HomeGrid](../src/pages/home/HomeGrid.tsx) enables all nine cards. [Settings](../src/pages/settings/SettingsPage.tsx) implements local preferences and encrypted-key management. [Inbox](../src/pages/inbox/InboxPage.tsx) owns a full-content webmail surface, configuration guidance and load recovery. [Ask AI](../src/pages/ai/AskAIPage.tsx) implements a persistent multi-session streaming Agent. [My Profile](../src/pages/profile/ProfilePage.tsx) implements manual editing and reviewed PDF import; Add Job and the Applications list are implemented; Tailor Resume is implemented; Interview Prep remains scaffolded.

## 2. Routes and mixed history

The [destination contract](../src/shared/navigation.ts) allowlists `app://home`, `app://find`, `app://resume`, `app://interview`, `app://applications`, `app://inbox`, `app://profile`, `app://browser`, `app://ai` and `app://settings`. Internal URLs are navigation identifiers, not registered OS protocols or documents loaded by Chromium. Unknown internal targets are rejected before changing history. Public URLs are owned by [product architecture](product-architecture.md).

[BrowserManager](../src/platform/browser/browserManager.ts) owns tabs, active destination and versioned snapshots. Each tab starts on Home. Home adds an internal history entry; new tabs and closing the final tab create fresh Home destinations. Selecting Browser adds an empty browser workspace with an empty address field. Selecting another tab never adds history. Closing the active tab selects its right neighbor, or its left neighbor if last.

[MixedHistory](../src/platform/browser/mixedHistory.ts) combines internal entries with continuous web-history segments. Each [WebSegment](../src/platform/browser/webSegment.ts) retains its own native view and Chromium history. Back/Forward traverse native indices inside a segment, then cross internal/segment boundaries. Internal navigation hides existing views without navigating or destroying them, preserving the current page state when returning directly. Normal Chromium history traversal may reload older documents.

New navigation after Back trims both the app forward stack and the current segment's native forward entries. Unreachable segments are closed; tab/window closure releases all retained views. Website links, redirects and SPA navigation update native history; traversal and replacement do not append app entries. Duplicate URLs retain native entry identity. The private [Chromium history observer](../src/platform/browser/nativeHistory.ts) reads stable entry IDs through the internal debugging protocol to distinguish new visits from website-driven traversal; it injects no page scripts and exposes no debugging bridge. Loading/error events remain associated with their original segment and never activate a background tab or internal page.

[Web input parsing](../src/platform/browser/navigationManager.ts) preserves HTTP(S), recognizes domains/IPs/localhost and searches other terms on Google. Bare addresses default to HTTPS; localhost and loopback default to HTTP. Empty input, invalid explicit web addresses and other schemes are rejected. [Tests](../tests/navigation.test.ts) retain those rules; [mixed-history tests](../tests/mixed-history.test.ts) cover internal routing and segment traversal/branching.

## 3. Presentation and interaction

[WorkspaceSidebar](../src/app/WorkspaceSidebar.tsx) remains beside every page, with Home, nine features, accessible translated groups and a single active item in an icon rail. The original Home / Job search / Manage / Tools / Settings sections remain in order, separated by short horizontal rules according to the [design specification](design-system.md#5-interaction-and-accessibility). Hover tooltips provide translated destination names; the sidebar brand header and Home brand eyebrow are removed. Shared [feature metadata](../src/app/navigation/features.ts) supplies both the sidebar and Home icons/order. Clicking another feature uses the same navigation API and unsaved-settings guard; selecting the current feature does not add history. [HomePage](../src/pages/home/HomePage.tsx) renders the launcher without a Back button. Other business pages provide only a Go home button for page navigation (Ask AI V2 uses the persistent sidebar Home entry), with no cross-page Back/Next/Forward controls. Scaffolded pages supply their own buttons and handlers through the [placeholder layout](../src/shared/ui/PlaceholderPage.tsx) action slot; the layout defines no navigation behavior. [Browser controls](../src/pages/browser/BrowserControls.tsx) retain Home, Back and Forward. Button ownership rules are defined in [code architecture](code-architecture.md#page-button-ownership).

**Implemented:** page controls/cards/icons reuse the [central UI components](../src/shared/ui/index.ts), styled by the [central runtime stylesheet](../src/shared/ui/components.css); page behavior remains local. [Shared tokens](../src/shared/ui/design-tokens.json) supply the 8px spacing, component sizes, typography and semantic colors used by [Home](../src/pages/home/home.css) and [application styles](../src/renderer/styles/global.css). The [design specification](design-system.md) owns those rules and the ten-category HTML reference gallery; gallery examples do not establish business functionality.

Only the active web segment can be shown. Browser segments start below its 48px tab strip and 48px toolbar (96px total, from [shared geometry](../src/shared/ui/geometry.ts)); Inbox segments start at `y = 0` and use the full content height; app tabs, address controls and a top bar remain absent. Both native surfaces start to the right of the sidebar, using [generated geometry](../src/shared/ui/geometry.ts): 64px at every window width. [Application layout](../src/renderer/styles/global.css) follows the same width token, keeping all sidebar controls outside the native view. The sidebar Home entry replaces the mailbox Exit footer. Each [WebSegment](../src/platform/browser/webSegment.ts) retains its surface across redirects, native navigation and pop-ups; switching between Browser and Inbox creates a separate segment. Bounds follow window resizing. Target transitions hide all native views until the owning page acknowledges the tab/target through [native presentation](../src/app/navigation/useNativePresentation.ts). Stale visibility requests are ignored. Renderer reload hides views while providers resubscribe, then restores Main's destination/history; it does not reset the tab to Home.

[TabStrip](../src/pages/browser/TabStrip.tsx) supports creation, selection, closure, scrolling and arrow/Home/End selection. Internal destinations use page titles in tab labels; `app://` text is never rendered. [AddressBar](../src/pages/browser/AddressBar.tsx) follows state while idle and preserves drafts while focused; changing tabs resets the input.

[Shortcuts](../src/platform/browser/shortcuts.ts) work from the trusted renderer and native pages: `Cmd+T/W` on macOS or `Ctrl+T/W` elsewhere create/close tabs; `Ctrl+Tab` and `Ctrl+Shift+Tab` cycle tabs. `Cmd+L`/`Ctrl+L` focuses/selects the address only on Browser. `Alt+Left/Right` traverses mixed history, including internal pages without browser chrome.

[Settings hook](../src/pages/settings/useSettings.ts) owns separate drafts and save feedback. Main confirms discarding unsaved Settings and Profile changes before navigation, history travel, tab switching/closure and window closure; stale draft registrations are ignored by tab/target identity. Refresh protection retains the current target/draft until navigation commits; cancelling refresh retains import sessions, and confirmed closure does not ask twice. Configured `app://inbox` resolves to the saved HTTPS webmail address with an Inbox surface before entering history; unconfigured Inbox shows setup guidance. Mailbox failures hide the native view and show page-owned retry/settings actions. Storage semantics belong to [data architecture](data-architecture.md#6-settings-secrets-and-remaining-work).

**Implemented external Agent setup:** [Settings](../src/pages/settings/ExternalMCPSettings.tsx) offers global MCP installation, confirmed replacement, clipboard export, independent connection checks, MCP reconnection/removal and separate bundled Skills installation, reconnection and selective removal through dedicated host IPC. Skills show per-item state, require confirmation before replacement without backups, and can be opened for manual copying to other Agents. Preference drafts are unchanged. Host boundaries, installation paths and limitations belong to [MCP architecture](mcp-architecture.md#5-job-agent-browser-mcp).

**Implemented Audit Viewer:** [Settings audit section](../src/pages/settings/AuditViewerSection.tsx) loads independently of preference forms through the [viewer hook](../src/pages/settings/useAuditViewer.ts). It provides 25-row pages, explicit filtering/refresh, metadata details, empty/error/retry states and discards superseded responses. Filters remain in page memory and do not mark preferences unsaved. Read semantics and audit scope belong to [data architecture](data-architecture.md#4-audit-and-transactions).

**Implemented themes:** Settings offers Light, Dark and Follow system through the existing central `Select`. Theme and language are general-setting drafts: Save applies them after a successful write; failed saves and discarded drafts retain the active theme. Light remains the default; preference storage semantics belong to [data architecture](data-architecture.md#6-settings-secrets-and-remaining-work).

[Main](../src/platform/electron/main/index.ts) applies the saved theme before window creation. The [theme adapter](../src/platform/electron/main/theme.ts) sets Electron `nativeTheme.themeSource`; [BrowserManager](../src/platform/browser/browserManager.ts) publishes resolved `BrowserState.theme` on native updates without changing navigation targets/history. [App ThemeProvider](../src/app/theme.tsx) applies the root theme before React paints updates; generated CSS uses the native color preference before the first snapshot. The [window](../src/platform/electron/main/window.ts) and retained [WebSegments](../src/platform/browser/webSegment.ts) use generated theme backgrounds; one window-owned listener updates all retained views and is removed on window disposal. Recreated windows inherit the current native theme.

Follow system responds to native appearance updates; explicit Light/Dark overrides the system. Remote Browser/Inbox documents receive Chromium color preferences and retain website-controlled appearance; no forced recoloring is injected. Theme styling changes colors only, as defined in the [design system](design-system.md#4-semantic-color-rules). The [focused theme runner](../scripts/theme-runtime-smoke.cjs) exercises this independently, including macOS window recreation; commands remain in README. Startup background matching reduces flashes; complete frame-level verification and native appearance review on Windows/Linux remain unverified.

[App Context](../src/app/context/appContext.ts) exposes the active page's tab/title/destination and nullable Job, Profile and Artifact IDs. The [reference store](../src/app/context/contextStore.ts) starts empty and does not copy entities or extract page content. Profile selects its valid referenced record, otherwise the most recently updated Profile, and updates the shared ID after loading/saving.

**Implemented AI:** [Main-owned service](../src/platform/ai/service.ts) snapshots the selected provider, model and credential at request creation. Only OpenAI-compatible Chat Completions is supported. The [shared transport](../src/platform/ai/transport.ts) uses `/v1` for bare endpoints such as `http://127.0.0.1:1234`; explicit API paths such as `/v1` or `/gateway/v1` are preserved, with trailing slashes removed. Streaming chat and the Resume Agent share this URL resolution. The [compatible adapter](../src/platform/ai/compatible.ts) consumes SSE; redirects are rejected. Remote endpoints require HTTPS; loopback HTTP supports local services. Automatic retries, cross-provider fallback and structured-output capability probing remain unimplemented.

[Legacy AI IPC](../src/platform/electron/main/ai-ipc.ts) exposes start/cancel and model discovery and returns events to the initiating trusted frame. [Renderer coordination](../src/app/ai/streamClient.ts) subscribes before invocation, buffers early events and removes subscriptions on terminal events or page disposal. The service bounds requests and context/output sizes, applies the saved AI request timeout to chat and cancels requests on renderer navigation/destruction or shutdown. Provider SSE remains in Main; incremental IPC drives the UI.

[Ask AI V2](../src/pages/ai/AskAIPage.tsx) uses [Main tasks](../src/platform/electron/ask-agent-tasks.ts), a streaming Agent loop and a scoped first-party MCP session. One Run is active per Session, with four per window/sixteen globally. Session switching and internal-page navigation preserve work; Stop, Renderer loss and shutdown cancel it. The [App projection](../src/app/ai/askStore.ts) subscribes before snapshot loading, deduplicates monotonic events and resynchronizes gaps. Sessions retain model choices; each Run captures configuration/credentials independently. Rename/delete, drafts, history pagination and safe manual retry are implemented; a run that attempted writes offers state review instead of automatic replay. Storage/privacy belongs to [data architecture](data-architecture.md); tool scope belongs to [MCP architecture](mcp-architecture.md).

[Streaming adaptation](../src/platform/ai/agent-stream.ts) normalizes content and explicitly public `reasoning_summary` string deltas. Unclassified `reasoning`/`reasoning_content` fields are ignored; models without summaries show Working and tool activity. Full tool batches are assembled, validated and audited before execution. [Ask AI smoke](../scripts/ask-ai-runtime-smoke.cjs) verifies real IPC/MCP, concurrency, bilingual 320/640/1200px layouts, restart and forced-process checkpoint recovery with local fixtures.

**Implemented model discovery:** [Main discovery](../src/platform/ai/models.ts) sends an explicit `GET` to the saved provider's `models` resource with its saved key, or no authorization for keyless services. A model/default is not required. It rejects redirects, bounds JSON to 1 MB/10,000 entries, validates/deduplicates/sorts IDs, and applies the saved model-detection timeout, at most one request per window and 16 globally. Window disposal/navigation or shutdown aborts detection.

[Settings selection](../src/pages/settings/ModelDiscovery.tsx) adds chosen IDs to the draft (up to 100); saving applies them. Empty/error responses preserve manual entry, and late results from changed providers/unmounted controls are ignored. Detection makes no generation call, writes no settings/audit entry, and does not certify chat/tool capability. [Regression tests](../tests/ai-models.test.ts) and [production smoke](../scripts/ai-smoke.cjs) use local fixtures; model discovery and a short streaming chat were also verified against local LM Studio. Other live services remain unverified.

**Implemented Profile:** [page state](../src/pages/profile/useProfile.ts) loads every item/fact page and groups facts beneath their owning experience, project or education entry; unattached facts have their own section. Editing and import drafts use the native leave guard plus refresh protection. Router targets remount page state; confirmed abandonment discards the import session. Storage and explicit-save semantics belong to [data architecture](data-architecture.md).

[Import IPC](../src/platform/electron/main/profile-import-ipc.ts) opens one native PDF selection and returns an opaque file ID. [The session service](../src/platform/profile-import/service.ts) owns bytes, tasks, draft IDs, save receipts and owner checks in memory. [PDF.js extraction](../src/platform/import/pdf-worker.mjs) runs in a cancellable Node Worker copied beside Main by the build; CMaps, standard fonts and WASM resolve from the installed dependency. Limits are 10 MB, 20 pages and 60,000 extracted characters, with explicit encrypted/corrupt/no-text/limit errors. Text line/column ordering is heuristic, so review remains necessary.

Main sends PDF text to the disclosed saved default Provider/model, reusing AI timeouts, cancellation and startup audit. [Draft parsing](../src/platform/profile-import/draft.ts) validates JSON and groups multiple facts per entry. Import output contains no source quotes/page numbers or evidence checks; optional empty fields may be omitted. Saved facts still support Resume Agent statement associations. Raw streams are never presented as parsed records. Retry is manual. Raw PDFs, full text and unsaved drafts are not persisted; leave, refresh, crash and window disposal release sessions. OCR, original-file management and third-party Provider compatibility certification remain unimplemented.

**Implemented import modes:** both imports start in Standard mode (`single`, one AI request). In Settings, select the Provider and the model under “Model for parallel import settings”, enable “Allow parallel imports for this model” and save. Then select Parallel (`parallel`) independently on the PDF or URL import page. The permission belongs to the Provider/model pair, not the model API. Import mode is page/session state, not a saved global preference; a missing permission disables Parallel and Main rejects attempts to bypass it. See [model controls](../src/pages/settings/ModelImportSettings.tsx), [mode controls](../src/app/ai/ImportControls.tsx) and [Main policy](../src/platform/import/policy.ts).

The page is downloaded/cleaned once or the PDF text is extracted once before AI work starts. [Job groups](../src/platform/job-import/parts.ts) and [profile groups](../src/platform/profile-import/parts.ts) read the same complete source; splitting does not partition the document by page. Ordinary and parallel PDF import use the same compact fact schema described in [data architecture](data-architecture.md#2-business-rules).

| Import | Group | Extracted content |
| --- | --- | --- |
| Job capture | `basics` | Title, raw company name, location text/list, employment type and salary |
| Job capture | `description` | Job description |
| Job capture | `requirements` | Requirement text, category and keywords |
| PDF profile | `contact` | Basic profile fields including introduction, links and standalone facts |
| PDF profile | `experience` | Work experience entries with their nested facts |
| PDF profile | `projects` | Project entries with their nested facts |
| PDF profile | `education` | Education entries with their nested facts |

In Parallel mode, job notes default to empty; source metadata is assembled locally. [Shared batches](../src/platform/import/batch.ts) permit at most three concurrent parts, so the fourth PDF group waits for a slot. Each group can return only its assigned fields/item types; deterministic merging happens after all groups succeed. Profile merging removes matching kind/content duplicates within a parent and matching standalone copies of attached facts; equal facts under different parents remain separate.

[The AI service](../src/platform/ai/service.ts) queues Profile imports within four active requests per window/sixteen globally and eighty accepted active/queued requests. Job Capture uses AgentModel with up to three concurrent groups per window-owned task. Each group reports memory-only queue/processing durations; [shared batches](../src/platform/import/batch.ts) refresh every 100 ms with a monotonic clock, preserve terminal durations and reset only failed parts on retry. Completion/failure/cancellation release the timer.

When a part fails, completed results remain in memory and the page offers “Retry failed parts” only when the task reports `retryable`. Retrying reuses the original source, model choice, mode and successful results; it neither downloads/extracts again nor writes business data. Read/extraction failures or final merge failures without a failed part require a fresh parse. Replacement, discard, navigation/window disposal and process exit release the relevant task/cache. Retry identifiers belong to [data architecture](data-architecture.md#5-api-contract-and-access).

Every group receives the full input, so input tokens/cost can increase. Smaller outputs and concurrent requests can reduce waiting, but provider concurrency, model throughput and network latency determine the result; local fixture tests do not establish a live-provider speedup.

**Implemented Add Job:** [the page](../src/pages/find-jobs/AddJobPage.tsx) supports manual entry and URL/text/PDF capture through [Capture Agent](../src/platform/agent/capture.ts). It fills empty fields, preserves existing arrays/salary and shows the selected model. Reading and interpretation make no JAB MCP calls; edited drafts are saved through job.import after review. Manual forms retain typed IPC. [Unsaved protection](../src/app/navigation/useUnsavedGuard.ts) is shared with Profile; storage rules belong to [data architecture](data-architecture.md).

[The public URL reader](../src/platform/job-import/url-reader.ts) reads HTTP(S) HTML in Main without website cookies or page scripts: the saved page-read timeout, up to 5 redirects, 2 MB HTML, 60,000 text characters and 40,000 JobPosting metadata characters. [HTML parsing](../src/platform/job-import/html.ts) uses htmlparser2 and excludes scripts/navigation. HTTP denials, detected login/challenge pages and unreadable content return fixed errors. Script-only pages and unrecognized challenges may fail; compatibility with all job sites is not guaranteed.

[Capture tasks](../src/platform/job-import/service.ts) own source bytes, draft state, retries and a stable save requestId per window. [Common PDF reading](../src/platform/import/pdf.ts) shares the Profile worker and limits. Job parsing uses AgentModel; [group parsing](../src/platform/job-import/parts.ts) rejects managed fields and preserves successful groups for retry. Window disposal suppresses late results. Authenticated Browser capture, login/captcha handling, OCR and original-file management remain unimplemented.

[Applications](../src/pages/applications/ApplicationsPage.tsx) supports search/status/archive filters, 25-row pages and explicit refresh. Details contain sources, paginated events and an [Application Agent panel](../src/pages/applications/ApplicationAgentPanel.tsx). Clear instructions execute local status/note/event/detail/archive actions through MCP; missing details trigger questions, and partial failures retain completed actions. Saving a Job opens its details. External calendar/email actions and duplicate merging remain planned.

**Implemented Resume Agent V1:** [Main tasks](../src/platform/electron/resume-tasks.ts) compose a fixed five-stage [Resume Agent](../src/platform/agent/resume.ts) and a real first-party stdio MCP session. Immutable start/read/submission/publish/fail/cancel/build all cross MCP; UI queries/preview/export remain separate Main operations. [The asynchronous bridge](../src/platform/electron/resume-contract.ts) powers Tailor Resume, retains history, limits one active task per window and cancels destroyed-window work. [Data architecture](data-architecture.md#3-generation-output-and-deletion) owns persistence/output; [MCP architecture](mcp-architecture.md) owns Agent boundaries.

## 4. Session, security and storage

Remote views share `persist:job-agent-browser`, retaining website storage across restarts. Permission requests are denied; there is no multi-profile selector.

- [Trusted window](../src/platform/electron/main/window.ts) and [remote views](../src/platform/browser/webSegment.ts) disable Node integration and enable context isolation and sandboxing; remote web security remains enabled.
- Browser, data and AI IPC require the owning trusted document and top frame, and validate inputs. [Preload](../src/platform/electron/preload/index.ts) exposes named operations, never raw `ipcRenderer`.
- Remote main-frame navigation/redirects permit HTTP(S) only. HTTP(S) pop-ups create an app tab; native pop-ups and other schemes are denied. Remote pages cannot enter internal routes or access browser/data bridges.
- [Trusted HTML](../src/renderer/index.html) retains its CSP. Trusted UI external links use the operating-system browser through window creation.

Main opens storage and registers data handlers before creating the window, closes storage on quit and reports startup failure without resetting data. [Backend composition](../src/platform/database/backend.ts) injects repositories/transactions and recovers interrupted generation attempts. The [data architecture](data-architecture.md) owns implemented SQLite, business validation, persistence and content-free audit.

**Implemented tools/MCP:** [Main](../src/platform/electron/main/index.ts) separately owns optional third-party consumption and [first-party sessions](../src/platform/mcp/first-party-client.ts). All four internal Agents and external hosts use the same 34-tool [Node Server](../src/platform/mcp-server/runtime.ts); caller labels affect audit only. Renderer exposes named workflow IPC, never generic tool execution. [MCP architecture](mcp-architecture.md) owns registration, bounds and shutdown; data architecture owns multi-process recovery.

## 5. Internationalization

**Implemented:** English and [Simplified Chinese resources](../src/shared/i18n/locales/zh-CN.ts) support saved language selection. [English resources](../src/shared/i18n/locales/en.ts) centralize application-owned page copy, internal titles, tooltips, accessible labels, errors and native startup dialogs. [Shared initialization](../src/shared/i18n/index.ts) creates a separate i18next instance in each process from bundled resources, synchronously with English as the default and fallback. No translation network requests or system-language detection occur.

[App translation provider](../src/app/i18n.tsx) supplies that Renderer instance to `useTranslation()` and updates document title/language. Non-React code uses the shared `t` function; [Main](../src/platform/electron/main/index.ts) can translate before React starts. [Build configuration](../electron.vite.config.ts) injects the HTML title from the same English resource used for the native window. Complete sentence templates interpolate labels/titles, and React renders the result as text. User data, website titles/content and diagnostic-only exceptions remain outside the catalog. Main loads the saved language before creating a window and publishes it in browser snapshots; Renderer follows that language through its provider. New browser title/error strings use the active language; previously captured error text is not retranslated.

**Planned:** further languages and system-language detection. [Translation tests](../tests/i18n.test.ts) cover startup readiness, fallback, instance isolation, React resource consumption, interpolation safety and invalid-key type checking.
