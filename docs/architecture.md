Status: **Implemented** React composition, separate workspace/browser navigation, Settings, Profile editing/PDF import, Job Capture/Application Agents, Unified Agent Runtime and Resume V3 with HTML/PDF. Smart Note is **Implemented**; additional product workflows remain **Planned**.

## 1. Runtime and process boundaries

[Build configuration](../electron.vite.config.ts) selects [Main](../src/platform/electron/main/index.ts), [Preload](../src/platform/electron/preload/index.ts), the isolated [Browser gesture preload](../src/platform/electron/preload/browser-gestures.ts), and the [Renderer HTML entry](../src/renderer/index.html). The [package entry](../package.json) remains `out/main/index.js`.

```text
React App → Page → Preload → IPC → Main
                                  ├── Tab navigation + WebContentsView → Session
                                  ├── Domain services → SQLite + audit
                                  ├── AI service → Provider SSE
                                  └── MCP Client → stdio Server → ToolScope → audited capability → Domain
```

The [Renderer bootstrap](../src/renderer/main.tsx) mounts the single [App](../src/app/App.tsx) in StrictMode. [Providers](../src/app/providers.tsx) inject controlled browser/data/AI bridges and context; the [navigation store](../src/app/navigation/navigationStore.ts) subscribes once per provider lifecycle and ignores older snapshots and disposed initialization reads. [Router](../src/app/router.tsx) selects React pages from Main's active destination without navigating the trusted document.

[BrowserPage](../src/pages/browser/BrowserPage.tsx) alone renders tabs, address input and browser controls. Other workspace pages hide browser chrome and internal URLs. [Settings](../src/pages/settings/SettingsPage.tsx) implements local preferences and encrypted-key management. [Inbox](../src/pages/inbox/InboxPage.tsx) owns a full-content webmail surface, configuration guidance and load recovery. [Ask AI](../src/pages/ai/AskAIPage.tsx) implements a persistent multi-session streaming Agent. [My Profile](../src/pages/profile/ProfilePage.tsx) implements manual editing and reviewed PDF import; Add Job and the Applications list are implemented; Tailor Resume is implemented; Smart Note is implemented.

## 2. Workspace routes and browser history

The [destination contract](../src/shared/navigation.ts) allowlists `app://find`, `app://resume`, `app://knowledge`, `app://applications`, `app://inbox`, `app://profile`, `app://browser`, `app://ai` and `app://settings`. Internal URLs are navigation identifiers, not registered OS protocols or documents loaded by Chromium. Unknown internal targets are rejected before changing history. Public URLs are owned by [product architecture](product-architecture.md).

[BrowserManager](../src/platform/browser/browserManager.ts) owns tabs, active destination and versioned snapshots. Startup opens Ask AI (`app://ai`); new tabs and closing the final tab open an empty Browser workspace. Selecting Browser resumes the retained webpage or an empty workspace. Selecting a tab from Browser stays in Browser, even if that tab last displayed a business page. Closing the active tab selects its right neighbor, or its left neighbor if last.

[TabNavigation](../src/platform/browser/tabNavigation.ts) separates the current workspace destination from retained Browser and Inbox surfaces. Each [WebSegment](../src/platform/browser/webSegment.ts) retains its native view and Chromium history. Back/Forward operate only inside the visible Browser surface; at its first/last entry they stop. Workspace pages and Inbox report both controls disabled and ignore travel requests. Visiting a workspace page preserves the browser position, forward entries and current webpage state; Chromium history traversal may reload older documents.

Opening a new web address after Back trims that surface's native forward entries; switching workspace pages does not. Each tab retains at most one Browser and one Inbox view; tab/window closure releases both. Website links, redirects and SPA navigation update native history; traversal and replacement do not append app entries. Duplicate URLs retain native entry identity. The private [Chromium history observer](../src/platform/browser/nativeHistory.ts) reads stable entry IDs through the internal debugging protocol to distinguish new visits from website-driven traversal; it injects no page scripts and exposes no debugging bridge. Loading/error events remain associated with their original segment and never activate a background tab or internal page.

[Web input parsing](../src/platform/browser/navigationManager.ts) preserves HTTP(S), recognizes domains/IPs/localhost and searches other terms on Google. Bare addresses default to HTTPS; localhost and loopback default to HTTP. Empty input, invalid explicit web addresses and other schemes are rejected. [Tests](../tests/navigation.test.ts) retain those rules; [tab-navigation tests](../tests/tab-navigation.test.ts) cover workspace isolation, retained forward history, Inbox separation and native traversal boundaries.

### Copy Webpage

**Implemented.** The Browser toolbar and native context menu copy the active Browser page at the time of the action. Toolbar calls pass through [trusted Renderer IPC](../src/platform/electron/main/browser-ipc.ts). [WebSegment](../src/platform/browser/webSegment.ts) parses a live main-document HTML snapshot in an isolated world and writes normalized body text to the system clipboard. Hidden body text is included, with script, style, embedded frame and shadow tree content excluded. Blank tabs, failed loads, and empty results leave the clipboard intact. The [Electron smoke](../scripts/browser-copy-smoke.cjs) covers both entries, tab changes, page copy restrictions, dynamic text and empty results.

### Web selection transfer

**Implemented:** [WebSegment](../src/platform/browser/webSegment.ts) handles native context menus for ordinary Browser selections, including Frames, and retains native editing actions. Inbox, form controls and editable regions have no business entries. Clicks recheck the active tab/target, source document generation and live Frame; reload/navigation or tab changes invalidate old menus. [Selection validation](../src/shared/browser-selection.ts) preserves up to 60,000 UTF-16 units, limits URL/title lengths and sanitizes source URL credentials, fragments and known authentication query parameters. Source attribution uses the top-level URL/title.

[BrowserManager](../src/platform/browser/browserManager.ts) stages a UUID-bound [memory handoff](../src/platform/browser/selectionHandoff.ts) before publishing the same-tab internal destination. Trusted Main-frame IPC reads by tab/target/page and ACKs after a committed input update. Retry is allowed for five minutes; navigation away, tab closure and shutdown clear pending content. Payloads never enter URLs, BrowserState, logs or audit. [Consumer](../src/app/navigation/useWebSelection.ts) ignores stale/unmounted responses and repeated application. Ask appends to the unsent new-chat draft without replacing session drafts or starting Runs; in-flight sends cannot reclaim that draft. Add Job selects Text and waits for Parse/Save. Transfer equals user input; ordinary subsequent persistence/export applies. Source persistence belongs to [data architecture](data-architecture.md#2-business-rules).

The existing `persist:job-agent-browser` Session remains shared across native views. [Selection smoke](../scripts/browser-selection-smoke.cjs) exercises real right-click events, Frames, source saving, explicit AI actions, login reuse/expiry/logout; [restart smoke](../scripts/settings-restart-smoke.cjs) verifies persistent cookies and localStorage against the same local origin in a fresh production process. JAB does not renew expired site sessions; live provider login compatibility remains unverified.

### Smart Paste and Global Banner

**Implemented:** Browser and Inbox offer saved Smart Paste prompts from the native context menu for supported text fields, including same-origin and cross-origin HTTP(S) frames. [The isolated preload](../src/platform/electron/preload/web-field.ts) locks the actual element and selection. [The host task](../src/platform/smart-paste/service.ts) opens a background Ask AI Session with the saved default model and streams assistant text into that range. Tool-turn preambles are withdrawn. Failure and cancellation retain written partial answers. User edits, a replaced field or frame navigation end writing. Switching workspace pages keeps a live target eligible. The website receives input events and retains responsibility for its form. [Smart Paste smoke](../scripts/smart-paste-smoke.cjs) runs with `npm run test:smoke -- --smart-paste`.

[The Main Banner](../src/platform/banner/bannerView.ts) stays above native web surfaces, uses one view and links to the associated Ask AI Session through guarded navigation. [Data architecture](data-architecture.md) owns Settings and transcript retention. [MCP architecture](mcp-architecture.md) owns the Smart Paste tool scope.

## 3. Presentation and interaction

[WorkspaceSidebar](../src/app/WorkspaceSidebar.tsx) places Ask AI first in the persistent icon rail, followed by the Manage, Job search and Tools groups and the Settings footer. Short rules separate the groups and translated labels appear on hover. Switching destinations uses the shared navigation API and leave guards. Select Ask AI from the sidebar on any workspace page. [Browser controls](../src/pages/browser/BrowserControls.tsx) provide Back, Forward and Refresh. See the [design specification](design-system.md#5-interaction-and-accessibility) and [page button ownership](code-architecture.md#page-button-ownership).

**Implemented:** page controls/cards/icons reuse the [central UI components](../src/shared/ui/index.ts), styled by the [central runtime stylesheet](../src/shared/ui/components.css); page behavior remains local. [Shared tokens](../src/shared/ui/design-tokens.json) supply the 8px spacing, component sizes, typography and semantic colors used by [application styles](../src/renderer/styles/global.css). The [design specification](design-system.md) owns those rules and the ten-category HTML reference gallery; gallery examples do not establish business functionality.

Only the active web segment can be shown. Browser segments start below its 48px tab strip and 48px toolbar (96px total, from [shared geometry](../src/shared/ui/geometry.ts)); Inbox segments start at `y = 0` and use the full content height; app tabs, address controls and a top bar remain absent. Both native surfaces start to the right of the sidebar, using [generated geometry](../src/shared/ui/geometry.ts): 64px at every window width. [Application layout](../src/renderer/styles/global.css) follows the same width token, keeping all sidebar controls outside the native view. Each [WebSegment](../src/platform/browser/webSegment.ts) retains its surface across redirects, native navigation and pop-ups; Browser and Inbox retain separate segments, and reopening unchanged Inbox configuration resumes its live page/draft; failed loads remain retryable. Bounds follow window resizing. Target transitions hide all native views until the owning page acknowledges the tab/target through [native presentation](../src/app/navigation/useNativePresentation.ts). Stale visibility requests are ignored. Renderer reload hides views while providers resubscribe, then restores Main's destination and history.

[TabStrip](../src/pages/browser/TabStrip.tsx) supports creation, selection, closure, scrolling and arrow/Home/End selection. Tab labels use the retained browser title or translated New tab, including when a background tab last displayed a business page; `app://` text is never rendered. [AddressBar](../src/pages/browser/AddressBar.tsx) follows state while idle and preserves drafts while focused; changing tabs resets the input.

[Shortcuts](../src/platform/browser/shortcuts.ts) work from the trusted renderer and native pages: `Cmd+T` on macOS or `Ctrl+T` elsewhere opens a new Browser tab from any page, honoring leave guards. Closing with `Cmd+W`/`Ctrl+W` and cycling with `Ctrl+Tab`/`Ctrl+Shift+Tab` operate only in Browser. `Cmd+L`/`Ctrl+L` focuses/selects the address only on Browser. `Alt+Left/Right` traverses only Browser webpage history and does nothing on workspace pages or Inbox.

### Browser history gestures

**Implemented:** [HistoryDrag](../src/platform/browser/historyDrag.ts) unifies right-button drags and horizontal touchpad wheel strokes. Rightward strokes indicate Back and leftward strokes indicate Forward; release after 96px (or a quarter of a narrow viewport) navigates once. The webpage, viewport and chrome stay fixed throughout. A sandboxed [native indicator](../src/platform/browser/historyIndicator.ts) displays the central arrow primitive at the corresponding content edge, highlights at the threshold and stays muted for unavailable directions. Short/reversed strokes dismiss the indicator without navigation or rebound. Indicator size/inset and gesture thresholds reuse generated token geometry; no gesture animation runs, including with reduced motion. Successful gestures commit immediately to the existing solid gray cover. Focus loss, resize, navigation, tab changes and disposal cancel pending gestures.

The isolated [gesture preload](../src/platform/electron/preload/browser-gestures.ts) handles trusted pixel-wheel events on the top document, leaving vertical/modified scrolling, editable fields, scrollable horizontal regions and CSS overscroll containment to the website. A wheel burst ends after 120ms without events; tail suppression limits repeated traversal. Wheel gestures starting inside child frames remain website-owned. Right clicks without a horizontal drag retain native menus; vertical mouse drags do not navigate. Inbox and workspace pages have no history gestures.

[History presentation](../src/platform/browser/historyPresentation.ts) keeps the old/partially painted document covered until two isolated animation frames and a compositor capture complete, then reveals directly without a fade or exit slide. Later navigation invalidates earlier readiness. Browser toolbar Back/Forward uses the same cover without hiding the native viewport between target acknowledgments. The neutral light/dark color is owned by the [design system](design-system.md).

[Refresh](../src/pages/browser/BrowserControls.tsx) follows Forward in the toolbar; it is disabled on empty/loading tabs. The sandboxed named [reload IPC](../src/platform/electron/main/browser-ipc.ts) reloads only the active Browser webpage. Native Browser/Inbox context menus also provide translated Refresh, reject stale/hidden-page clicks, and use the same gray-to-ready presentation; they do not reload the trusted application document.

[Wheel IPC](../src/platform/browser/historyGesture.ts) accepts only the view’s own top-frame preload, bounded deltas and the current document epoch while its Browser target is active; it exposes no API to websites. [Gesture tests](../tests/history-drag.test.ts) cover direction/threshold/reversal, boundaries, narrow viewport thresholds and stale cancellation. [Gesture smoke](../scripts/history-gesture-smoke.cjs) replays the native mouse hook (Electron synthetic mouse input bypasses it) and sends real Chromium wheel events to verify navigation, edge arrows/readiness, fixed content and chrome, held-frame gray presentation, toolbar/menu refresh, website scrolling and cancellation. Physical device feel and OS-specific momentum still need manual review.

[Settings hook](../src/pages/settings/useSettings.ts) owns separate drafts and save feedback. Main confirms discarding unsaved Settings and Profile changes before navigation, tab switching/closure and window closure; stale draft registrations are ignored by tab/target identity. Refresh protection retains the current target/draft until navigation commits; cancelling refresh retains import sessions, and confirmed closure does not ask twice. Configured `app://inbox` resolves to the saved HTTPS webmail address with an Inbox surface before activating the surface; unconfigured Inbox shows setup guidance. Mailbox failures hide the native view and show page-owned retry/settings actions. Storage semantics belong to [data architecture](data-architecture.md#6-settings-secrets-and-remaining-work).

**Implemented external Agent setup:** [Settings](../src/pages/settings/ExternalMCPSettings.tsx) offers global MCP installation, confirmed replacement, clipboard export, independent connection checks, MCP reconnection/removal and separate bundled Skills installation, reconnection and selective removal through dedicated host IPC. Skills show per-item state, require confirmation before replacement without backups, and can be opened for manual copying to other Agents. Preference drafts are unchanged. Host boundaries, installation paths and limitations belong to [MCP architecture](mcp-architecture.md#5-job-agent-browser-mcp).

**Implemented Audit Viewer:** [Settings audit section](../src/pages/settings/AuditViewerSection.tsx) loads independently of preference forms through the [viewer hook](../src/pages/settings/useAuditViewer.ts). It provides 25-row pages, explicit filtering/refresh, metadata details, empty/error/retry states and discards superseded responses. Filters remain in page memory and do not mark preferences unsaved. Read semantics and audit scope belong to [data architecture](data-architecture.md#4-audit-and-transactions).

**Implemented themes:** Settings offers Light, Dark and Follow system through the existing central `Select`. Theme and language are general-setting drafts: Save applies them after a successful write; failed saves and discarded drafts retain the active theme. Light remains the default; preference storage semantics belong to [data architecture](data-architecture.md#6-settings-secrets-and-remaining-work).

[Main](../src/platform/electron/main/index.ts) applies the saved theme before window creation. The [theme adapter](../src/platform/electron/main/theme.ts) sets Electron `nativeTheme.themeSource`; [BrowserManager](../src/platform/browser/browserManager.ts) publishes resolved `BrowserState.theme` on native updates without changing navigation targets/history. [App ThemeProvider](../src/app/theme.tsx) applies the root theme before React paints updates; generated CSS uses the native color preference before the first snapshot. The [window](../src/platform/electron/main/window.ts) and retained [WebSegments](../src/platform/browser/webSegment.ts) use generated theme backgrounds; one window-owned listener updates all retained views and is removed on window disposal. Recreated windows inherit the current native theme.

Follow system responds to native appearance updates; explicit Light/Dark overrides the system. Remote Browser/Inbox documents receive Chromium color preferences and retain website-controlled appearance; no forced recoloring is injected. Theme styling changes colors only, as defined in the [design system](design-system.md#4-semantic-color-rules). The [focused theme runner](../scripts/theme-runtime-smoke.cjs) exercises this independently, including macOS window recreation; commands remain in README. Startup background matching reduces flashes; complete frame-level verification and native appearance review on Windows/Linux remain unverified.

[App Context](../src/app/context/appContext.ts) exposes the active page's tab/title/destination and nullable Job, Profile and Artifact IDs. The [reference store](../src/app/context/contextStore.ts) starts empty and does not copy entities or extract page content. Profile selects its valid referenced record, otherwise the most recently updated Profile, and updates the shared ID after loading/saving.

**Implemented AI:** [Main-owned service](../src/platform/ai/service.ts) snapshots the selected provider, model and credential at request creation. OpenAI-compatible Chat Completions are supported; Knowledge embeddings use the separate bundled local runtime described below. The [shared transport](../src/platform/ai/transport.ts) uses `/v1` for bare endpoints such as `http://127.0.0.1:1234`; explicit API paths such as `/v1` or `/gateway/v1` are preserved, with trailing slashes removed. Streaming chat and the Resume Agent share this URL resolution. The [compatible adapter](../src/platform/ai/compatible.ts) consumes SSE; redirects are rejected. Remote endpoints require HTTPS; loopback HTTP supports local services. Automatic retries, cross-provider fallback and structured-output capability probing remain unimplemented.

[Legacy AI IPC](../src/platform/electron/main/ai-ipc.ts) exposes start/cancel and model discovery and returns events to the initiating trusted frame. [Renderer coordination](../src/app/ai/streamClient.ts) subscribes before invocation, buffers early events and removes subscriptions on terminal events or page disposal. The service bounds requests and context/output sizes, applies the saved AI request timeout to chat and cancels requests on renderer navigation/destruction or shutdown. Provider SSE remains in Main; incremental IPC drives the UI.

[Ask AI V2](../src/pages/ai/AskAIPage.tsx) uses [Main coordination](../src/platform/electron/ask-agent-tasks.ts) and one [Pi Agent](../src/platform/agent/pi/runtime.ts) per active Run. Each Session admits Runs FIFO through capability resolution, Core loading, context preparation, sequential inference/tools and terminal persistence; different Sessions can run concurrently. Later inputs persist Pending, bounded by four Runs per window/sixteen globally. Stop cancels the current chain and preserves partial content/committed writes; interrupted Runs never resume. Persistence-only recovery holds that Session's queue without replaying tools. [App projection](../src/app/ai/askStore.ts) resynchronizes monotonic events and retains drafts/pagination. Storage and MCP policy belong to their owning documents. Every admitted Send has an isolated, trusted MCP Run identity; [MCP architecture](mcp-architecture.md#ask-run-protection) owns protection/termination, and [model observation](../src/platform/agent/pi/request-observer.ts) caps main-loop plus summary requests at 64. The [Cycle state machine](agent-runtime.md) governs each Pi decision and tool batch. Execution status comes from the latest Cycle.

**Implemented request verification:** [stable provider names](../src/platform/ai/agent-protocol.ts) retain a semantic slug plus a short hash and a logical-name description prefix. The [Pi adapter](../src/platform/agent/pi/model-adapter.ts) verifies runtime loadout, Pi declarations and prepared provider names/full input-schema fingerprints before dispatch; mismatches stop with AGENT_PROTOCOL_ERROR. [MCP architecture](mcp-architecture.md) owns activation loop limits; [data architecture](data-architecture.md#ask-ai-transcript-storage) owns deletable per-request diagnostics. [Disclosure integration tests](../tests/ask-disclosure.test.ts) exercise real HTTP and first-party MCP without automatic fixture activation; live-model selection quality remains unverified.

[Streaming adaptation](../src/platform/ai/agent-stream.ts) and [reasoning normalization](../src/platform/ai/reasoning.ts) expose returned `reasoning_content`, `reasoning`, `reasoning_summary` and readable `reasoning_details` blocks with source/type metadata and mirrored-field deduplication. Encrypted blocks show an unavailable marker; absent reasoning shows Working. These shapes are fixture-tested, not a claim of arbitrary provider-format compatibility. Pi preserves Host-only continuation state across tool requests; [data architecture](data-architecture.md#ask-ai-transcript-storage) owns persistence. Full tool batches are assembled, validated and audited before execution. [Ask AI smoke](../scripts/ask-ai-runtime-smoke.cjs) verifies real IPC/MCP, concurrency, bilingual 320/640/1200px layouts, restart and forced-process checkpoint recovery with local fixtures.

[SessionSidebar](../src/pages/ai/SessionSidebar.tsx) confirms Copy Debug JSON through App-injected Data IPC; the full persisted snapshot stays in Main until clipboard readback succeeds, as specified in [data architecture](data-architecture.md#copy-debug-json).

[Context management](../src/platform/agent/context/manager.ts) checks each request against the effective model window, reserves output/safety space, and synchronously compacts completed turns at 80% toward 60%; validated checkpoints save before inference resumes. Core/recall/summary budgets are 2,048/2,048/4,096 tokens (recall uses approximate retrieval units). [Core loading](../src/platform/agent/context/core-memory.ts) reads CORE.md through MCP each admitted turn, treats absence as empty and locally truncates only the injected reference view, including its marker; it never invokes a model or automatically recalls L2. [Capability resolution](../src/platform/ai/ask-capabilities.ts) prefers LM Studio loaded-instance limits; unknown or sub-64K windows cannot start Ask AI. Settings accepts explicit deployment limits.

[Ask policy](../src/platform/agent/ask.ts) makes Pi solely responsible for reasoning, tools and durable Memory decisions. Projects/experience/skills use Profile items/Facts; basics use profile.get, saved jobs use Job tools, preferences use Memory and notes use Knowledge. Multiple ambiguous profiles require a question; after two source calls without new information the Prompt requires switching source or answering confirmed findings with missing information stated. Fit analysis reads Job/Profile/Facts; resume requests are directed to Tailor Resume without automatic generation. The [MCP policy](mcp-architecture.md) enforces the Ask subset and bounded recovery. [Routing fixtures](../tests/ask-routing.test.ts) verify the integration; live-model routing quality remains unverified.

**Implemented model discovery:** [Main discovery](../src/platform/ai/models.ts) sends an explicit `GET` to the saved provider's `models` resource with its saved key, or no authorization for keyless services. A model/default is not required. It rejects redirects, bounds JSON to 1 MB/10,000 entries, validates/deduplicates/sorts IDs, and applies the saved model-detection timeout, at most one request per window and 16 globally. Window disposal/navigation or shutdown aborts detection.

[Settings selection](../src/pages/settings/ModelDiscovery.tsx) adds chosen IDs to the draft (up to 100); saving applies them. Empty/error responses preserve manual entry, and late results from changed providers/unmounted controls are ignored. Detection makes no generation call, writes no settings/audit entry, and does not certify chat/tool capability. [Regression tests](../tests/ai-models.test.ts) and [production smoke](../scripts/ai-smoke.cjs) use local fixtures; model discovery and a short streaming chat were also verified against local LM Studio. Other live services remain unverified.

**Implemented Profile:** [page state](../src/pages/profile/useProfile.ts) loads every item/fact page and groups facts beneath their owning experience, project or education entry; unattached facts have their own section. Editing and import drafts use the native leave guard plus refresh protection. Router targets remount page state; confirmed abandonment discards the import session. Storage and explicit-save semantics belong to [data architecture](data-architecture.md).

[Import IPC](../src/platform/electron/main/profile-import-ipc.ts) opens one native PDF selection and returns an opaque file ID. [The session service](../src/platform/profile-import/service.ts) owns bytes, tasks, draft IDs, save receipts and owner checks in memory. [PDF.js extraction](../src/platform/import/pdf-worker.mjs) runs in a cancellable Node Worker copied beside Main by the build; CMaps, standard fonts and WASM resolve from the installed dependency. Limits are 10 MB, 20 pages and 60,000 extracted characters, with explicit encrypted/corrupt/no-text/limit errors. Text line/column ordering is heuristic, so review remains necessary.

Main sends numbered PDF text to the selected model. [Draft parsing](../src/platform/profile-import/draft.ts) validates source locations, sorts entries and deduplicates facts. Review can assign unclassified source lines to fields or facts, or ignore them. PDF bytes, full text and unsaved drafts stay in memory.

[Profile import requests](../src/platform/import/request.ts) and job capture each use one model request per parse. Explicit retry after a parse failure reuses the cached source and reruns the whole extraction. Cancellation, replacement or window disposal release task caches.

**Implemented Add Job:** [the page](../src/pages/find-jobs/AddJobPage.tsx) supports manual entry and URL/text/PDF capture through [Capture Agent](../src/platform/agent/capture.ts). It fills empty fields, preserves existing arrays/salary and shows the selected model. Reading and interpretation make no JAB MCP calls; edited drafts are saved through job.import after review. Manual forms retain typed IPC. [Unsaved protection](../src/app/navigation/useUnsavedGuard.ts) is shared with Profile; storage rules belong to [data architecture](data-architecture.md).

[The public URL reader](../src/platform/job-import/url-reader.ts) reads HTTP(S) HTML in Main without website cookies or page scripts: the saved page-read timeout, up to 5 redirects, 2 MB HTML, 60,000 text characters and 40,000 JobPosting metadata characters. [HTML parsing](../src/platform/job-import/html.ts) uses htmlparser2 and excludes scripts/navigation. HTTP denials, detected login/challenge pages and unreadable content return fixed errors. Script-only pages and unrecognized challenges may fail; compatibility with all job sites is not guaranteed.

[Capture tasks](../src/platform/job-import/service.ts) own source data, draft state, retries and stable save request IDs per window. [Job parsing](../src/platform/agent/capture.ts) uses AgentModel and suppresses late results after disposal. PDF reading shares the Profile worker and limits.

[Applications](../src/pages/applications/ApplicationsPage.tsx) supports search/status/archive filters, 25-row pages and explicit refresh. Details contain sources, paginated events and an [Application Agent panel](../src/pages/applications/ApplicationAgentPanel.tsx). Clear instructions execute local status/note/event/detail/archive actions through MCP; missing details trigger questions, and partial failures retain completed actions. Saving a Job opens its details. External calendar/email actions and duplicate merging remain planned.

**Implemented Resume V3.** [Main tasks](../src/platform/electron/resume-tasks.ts) copy the saved Profile over MCP and use the [shared Agent Engine](../src/platform/agent/engine/index.ts) to tailor existing bullets. [Tailor Resume](../src/pages/tailor-resume/TailorResumePage.tsx) shows business progress, history and HTML/PDF preview, with [Agent Trace](../src/pages/tailor-resume/ResumeTraceView.tsx) in a default-collapsed card below progress. ## 4. Session, security and storage

Remote views share `persist:job-agent-browser`, retaining website storage across restarts. Permission requests are denied; there is no multi-profile selector.

- [Trusted window](../src/platform/electron/main/window.ts) and [remote views](../src/platform/browser/webSegment.ts) disable Node integration and enable context isolation and sandboxing; remote web security remains enabled.
- Business browser, data and AI IPC require the owning trusted document and top frame, and validate inputs. [Preload](../src/platform/electron/preload/index.ts) exposes named operations, never raw `ipcRenderer`.
- Remote main-frame navigation/redirects permit HTTP(S) only. HTTP(S) pop-ups create an app tab; native pop-ups and other schemes are denied. Remote pages cannot enter internal routes or access browser/data bridges.
- [Trusted HTML](../src/renderer/index.html) retains its CSP. Trusted UI external links use the operating-system browser through window creation.

Main opens storage and registers data handlers before creating the window, closes storage on quit and reports startup failure without resetting data. [Backend composition](../src/platform/database/backend.ts) injects repositories/transactions and recovers interrupted generation attempts. The [data architecture](data-architecture.md) owns implemented SQLite, business validation, persistence and content-free audit.

**Implemented tools/MCP:** [Main](../src/platform/electron/main/index.ts) separately owns optional third-party consumption and [first-party sessions](../src/platform/mcp/first-party-client.ts). Internal workflows and external hosts share scoped business capabilities through the [Node Server](../src/platform/mcp-server/runtime.ts); caller labels affect audit only. Renderer exposes named workflow IPC, never generic tool execution. [MCP architecture](mcp-architecture.md) owns registration, bounds and shutdown; data architecture owns multi-process recovery.

## 5. Internationalization

**Implemented:** English and [Simplified Chinese resources](../src/shared/i18n/locales/zh-CN.ts) support saved language selection. [English resources](../src/shared/i18n/locales/en.ts) centralize application-owned page copy, internal titles, tooltips, accessible labels, errors and native startup dialogs. [Shared initialization](../src/shared/i18n/index.ts) creates a separate i18next instance in each process from bundled resources, synchronously with English as the default and fallback. No translation network requests or system-language detection occur.

[App translation provider](../src/app/i18n.tsx) supplies that Renderer instance to `useTranslation()` and updates document title/language. Non-React code uses the shared `t` function; [Main](../src/platform/electron/main/index.ts) can translate before React starts. [Build configuration](../electron.vite.config.ts) injects the HTML title from the same English resource used for the native window. Complete sentence templates interpolate labels/titles, and React renders the result as text. User data, website titles/content and diagnostic-only exceptions remain outside the catalog. Main loads the saved language before creating a window and publishes it in browser snapshots; Renderer follows that language through its provider. New browser title/error strings use the active language; previously captured error text is not retranslated.

**Planned:** further languages and system-language detection. [Translation tests](../tests/i18n.test.ts) cover startup readiness, fallback, instance isolation, React resource consumption, interpolation safety and invalid-key type checking.

## Smart Note knowledge

The **Implemented Memory v1:** [SmartNoteWorkspace](../src/platform/knowledge/workspace.ts) owns two fixed-root Markdown service views, one Git repository/lock, watcher, automatic backup and shared resources. [Storage architecture](data-architecture.md#smart-note-storage-and-memory-v1) owns migration/recovery and sync-consent semantics. Independent MCP cannot migrate or recover an incomplete workspace; it asks the user to start JAB.

The [workspace queue](../src/platform/knowledge/workspace-embedding.ts) serializes one shared provider, bounds queued work and prioritizes queries. Rebuilding one index drains its own work without cancelling or disposing the shared model; global configuration/removal/shutdown coordinates both views. The [broker](../src/platform/knowledge/broker.ts) depends only on shared query-vector generation, never a space's index. Standalone MCP loads no model and retains lexical fallback when Main/model is unavailable.

[Trusted IPC](../src/platform/electron/knowledge-contract.ts) retains `window.knowledge`, adding optional space to file/search/history/restore/index calls (default Knowledge); sync/configuration/model/backup stay workspace-wide. The [editor hook](../src/pages/knowledge/useKnowledge.ts) captures space/revision per save, flushes before selection and retains draft/selection on failure. Memory is a pinned collapsed Explorer root; searches reject late results from another scope and relative links stay in the current file's space. [UI rules](design-system.md#smart-note-knowledge) own shared controls; [MCP architecture](mcp-architecture.md#smart-note-knowledge) owns launch authorization and Ask Memory write authorization. Ask V2 runtime behavior is described above.

[Local embeddings](../src/platform/knowledge/rag/local-embedding.ts) lazily schedule one CPU [utility process](../src/platform/knowledge/rag/embedding-process.ts), prioritize queries, bound the queue and reject cancellation/timeouts/crashes. The worker disables remote loading/fetch and reads only a fully verified revision in the user model store. Main’s [Model Manager](../src/platform/models/manager.ts) owns download/Seed import, retry/cancel, checksums, atomic commit and removal; [paths](../src/platform/models/paths.ts) are independent of installation/cwd. GUI startup does not await model verification or import; unavailable models retain lexical search. Activation immediately schedules missing vectors, and removal stops local inference before deleting weights. Cross-process reader leases prevent replacing/removing another instance’s active model. [Packaging](ci-cd.md) owns distribution checks.

The [bootstrap](../src/platform/electron/main/bootstrap.ts) dispatches packaged child roles before loading Main; the application entry is application-main.js. PDF workers announce readiness before receiving input and use disposable userData removed by the parent. [Package verification](../src/platform/electron/verify-resume-package.ts) also executes a full MCP resume workflow, renders HTML/PDF and extracts text through the bundled PDF worker.

[npm adapter](../packages/npm/bin/jab.cjs) starts the same Electron bootstrap and exposes version/doctor/stdio MCP commands. npm uses the JAB application-data directory by default and accepts an explicit absolute override. DMG/npm credentials require clean-Mac compatibility testing; decryption failures preserve ciphertext and report an error. Models and application installs have independent lifetimes; automatic application updates remain unimplemented.
