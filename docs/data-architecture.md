# V1 Data Architecture and API

Purpose: define implemented local storage and business API boundaries. Status: **Implemented** transactional SQLite/audit, Settings/secrets, Profile editing/import, Job Capture/Application Agents and Resume V3 with immutable evidence, HTML/PDF output and asynchronous IPC. Remaining product flows are **Planned**.

## 1. Runtime and storage

[Main](../src/platform/electron/main/index.ts) and the [local MCP Server](../src/platform/mcp-server/runtime.ts) each open one `node:sqlite` connection to the explicit userData database. [SQLite initialization](../src/platform/database/sqlite.ts) enables foreign keys, WAL, full synchronous durability and a 1-second busy timeout. Renderer receives no SQL. [App Context](../src/app/context/appContext.ts) holds Job/Profile/Artifact IDs rather than record copies.

[Versioned migrations](../src/platform/database/migrations/index.ts) recognize database generation `0x4a415632` before journal/schema writes. Only empty or matching-generation databases are accepted; legacy databases fail with `INCOMPATIBLE_DATABASE_GENERATION` and are never reset, deleted or migrated. Development/acceptance must use separate userData. Matching databases use transactional migrations/checksums; future versions and mismatches fail startup. UUID v4 IDs cannot be reused after deletion; timestamps are UTC ISO strings.

The [shared ER diagram](diagrams/data-model.md) describes the implemented model. Concrete SQL types, defaults, nullability, checks and indexes live in [the schema](../src/platform/database/migrations/schema.ts) and [version-2 audit migration](../src/platform/database/migrations/ai-audit.ts), which preserves existing records and the 15 audit columns while extending fixed error codes. JSON uses validated TEXT columns; SQL tables are STRICT. Applications and Calendar use Job and JobEvent, without separate application/calendar tables.

| Tables | Ownership |
| --- | --- |
| `companies`, `jobs`, `job_sources` | Company identity, job details and preserved source content |
| `job_events` | Application lifecycle, schedules and notes |
| `profiles`, `profile_items`, `facts` | Contact information, personal introduction, structured containers and selectable evidence |
| `generation_runs`, `artifacts`, `artifact_facts` | Immutable inputs, generation stages, output and provenance |
| `audit_logs` | Content-free success/failure events |
| `capability_audit` | Content-free access/execution audit owned by read/write capabilities; [version-3 schema](../src/platform/database/migrations/capability-audit.ts) |
| `runtime_instances`, `runtime_work`, `invocation_owners`, `resume_start_receipts` | Process/work ownership, invocation ownership and atomic start receipts; [version-4 schema](../src/platform/database/migrations/runtime-leases.ts) |
| `operation_receipts` | Cross-session write receipts; [version-5 schema](../src/platform/database/migrations/operation-receipts.ts) and [version-8 extension](../src/platform/database/migrations/profile-writes.ts) |
| `chat_sessions`, `agent_runs`, `agent_items` | Host-owned transcript/model snapshots, request receipts, ordered visible items; [version 19](../src/platform/database/migrations/agent-storage.ts) |

## 2. Business rules

[Job use cases](../src/domain/job/job.service.ts) accept allowlisted details. Sources normalize URL fragments/query order and hash cleaned content; public-URL extraction is implemented; duplicate matching/merging remain planned. Archiving is independent of application status. Deleting a Company detaches Jobs and preserves their raw company names.

[Add Job](../src/pages/find-jobs/AddJobPage.tsx) uses typed IPC for manual saves and MCP job.import for reviewed Agent drafts; both reuse jobs.saveJob atomically. Title/company are required, new jobs are NOT_STARTED with null application/closure dates and no event. URL/text/PDF parsing does not write business tables; optional genuine web source is retained only on Save. Manual text/PDF uses source:null. Browser-prefilled Text retains its sanitized top-level URL, title, hostname and final edited text as the existing SourceDetails on Save, even when parsing returns source:null; changing source mode clears that binding. Durable receipts are described below.

[Application use cases](../src/domain/application/application.service.ts) write status changes and timeline events atomically. Allowed transitions are:

| Current status | Allowed next statuses |
| --- | --- |
| `NOT_STARTED` | `PREPARING`, `APPLIED`, `WITHDRAWN` |
| `PREPARING` | `NOT_STARTED`, `APPLIED`, `WITHDRAWN` |
| `APPLIED` | `INTERVIEW`, `OFFER`, `REJECTED`, `WITHDRAWN` |
| `INTERVIEW` | `OFFER`, `REJECTED`, `WITHDRAWN` |
| `OFFER` | `ACCEPTED`, `REJECTED`, `WITHDRAWN` |
| `ACCEPTED`, `REJECTED`, `WITHDRAWN` | Terminal; no status change |

Archived Jobs reject status changes and scheduling/rescheduling but permit notes and detail edits. Same-state status requests return unchanged data without duplicate events; same-value detail/archive/reschedule requests do not mutate. [Application workflow](../src/domain/application/workflow.ts) owns transitions and allowedNextStatuses. APPLIED sets application time and terminal states set closure time. System-created status events cannot be deleted independently. Calendar bounds are inclusive; email synchronization remains planned.

[Candidate use cases](../src/domain/candidate/candidate.service.ts) enforce same-profile parent/fact references, acyclic item nesting, valid date ranges and immutable item type. Item kinds are `EXPERIENCE / PROJECT / EDUCATION`. Fact kinds are `ACHIEVEMENT / RESPONSIBILITY / SKILL / AWARD / CERTIFICATION / COURSE / LANGUAGE / OTHER`. All saved Facts may participate in generation; no confirmation status, column or operation exists.

`Profile.introduction` is optional personal wording (up to 2,000 characters), separate from contact-only resume basics and item summaries. [Version-7 migration](../src/platform/database/migrations/profile-introduction.ts) adds an empty default without changing historical snapshots. [Profile editing](../src/domain/candidate/candidate.service.ts) preserves omitted introductions and accepts explicit clearing; [import review](../src/platform/profile-import/draft.ts) preserves source wording, ignores missing/blank introductions by default, and only replaces existing text after review.

[MCP profile commands](../src/domain/candidate/write.service.ts) add creation and partial updates while retaining same-profile references, date validation and immutable item types. Unrelated patches preserve incomplete imported fields; new profiles/items/facts still require names/titles/content. [Version 8](../src/platform/database/migrations/profile-writes.ts) initializes `Profile.revision` to 1. Database triggers monotonically advance it for actual contact, item or fact changes, including UI/import writes and deletion/cascades. MCP updates and item/fact additions require expectedRevision, checked in the same BEGIN IMMEDIATE transaction as business rows and receipts. No-op patches do not advance it. Receipt replay precedes version checks and returns the original result/historical revision; reread the live version afterwards. Only MCP writes supplying expectedRevision use optimistic concurrency; existing human forms retain their original IPC save semantics.

Each `ProfileItem` owns zero or more independently selectable Facts; each Fact belongs to one Profile and optionally one item in it. `parentItemId` relates items to items. Standalone skills/languages use a null `profileItemId`; fact kind does not determine ownership. `summary` stores background, while responsibilities/achievements remain individual Facts. The [fact service](../src/domain/candidate/fact.service.ts) validates edits and ownership. [Migration 15](../src/platform/database/migrations/remove-fact-evidence.ts) deletes `facts.evidence` and the same field in historical snapshot Facts and fact receipt results, preserving all other business values, revisions, timestamps and audit rows. Snapshot immutability and write guards are restored within the migration transaction. Old request hashes remain unchanged; pre-upgrade add requests may conflict on replay and must be reconciled by rereading saved records.

[Item validation](../src/domain/candidate/candidate.validation.ts) supports `metadata.startDateText` / `endDateText` (`YYYY`, `YYYY-MM`, `YYYY-MM-DD`) and `isCurrent`. Import/manual UI writes day columns only for complete dates, validates ranges and never supplies missing months/days. The new database generation preserves partial-date precision in JSON metadata.

[Explicit import](../src/domain/candidate/import.service.ts) atomically applies submitted contact fields, appends links and inserts items/Facts. The [review selection](../src/pages/profile/import-state.ts) saves all valid, non-ignored content; any non-ignored invalid entry blocks submission and focuses its invalid field. Ignoring a parent excludes its facts. Import allows empty or omitted names, titles, fact content and link labels/URLs; filled values retain format, date-range and length checks. Manual creation still requires a name. [Main sessions](../src/platform/profile-import/service.ts) enforce ownership, draft IDs, parent mappings, consumed entries and identical batch replay receipts. Partial saves retain parents for later facts. Duplicate uploads deliberately create new sessions; replay receipts are memory-only and cleared with the window/session.

[Import](../src/domain/candidate/import.service.ts) commits records and `PROFILE_IMPORT` audit entries together. It reserves item and fact ordering ranges for each import and uses the original source position across batches. [Migration 18](../src/platform/database/migrations/resume-module.ts) adds ordering and revision fields. Existing facts keep their timestamp order. PDF page and line anchors belong to the transient review draft.

## 3. Generation, output and deletion

[Resume start](../src/domain/resume/resume.service.ts) freezes the saved Job, Profile, Items, Facts and configuration in one transaction and copies them into a [ResumeDocument](../src/domain/resume/document.ts). Contacts and introduction supply basics and summary. Item metadata and order come from the snapshot. Facts with text keep source order, and a nonduplicate Item summary precedes its Facts. Unattached SKILL Facts supply Skills. Other unattached Facts and blank imported Facts remain in the snapshot.

[Generation states](../src/domain/resume/state-machine.ts) progress through `CREATED → COPYING → REWRITING → VALIDATING → PUBLISHING → PUBLISHED`. Unpublished Runs can become `FAILED`, `CANCELLED` or `INTERRUPTED`. State changes increment `stateVersion`. Each bullet may change once per GenerationRun. Unchanged text does not consume that change. The document, receipt and prior-change check share one BEGIN IMMEDIATE transaction. Identical request IDs and payloads replay their receipts. New requests for a changed bullet conflict. [Migration 21](../src/platform/database/migrations/resume-once.ts) removes the shared rewrite revision and preserves historical receipts and their hash inputs, including multiple earlier changes to the same bullet. Fact IDs and all other fields are fixed. The word target guides rewriting. Structural and size validation does not establish semantic accuracy. [Generation service](../src/domain/resume/generation.service.ts)

Publishing commits the Artifact, its Fact links, and `PUBLISHED` together. File output can fail independently. Desktop runs link to an Agent Run before inference. External hosts use the same business state with no local Agent Run. [MCP contracts](mcp-architecture.md#5-job-agent-browser-mcp)

[Migration 19](../src/platform/database/migrations/agent-storage.ts) preserves chat and trace identity. [Migration 20](../src/platform/database/migrations/resume-v3.ts) maps old running tasks to interrupted, preserves published artifacts and files, and retains retired fields as read-only history. Close the app and its MCP hosts and back up the complete userData directory before upgrading. To return to v18, restore that backup with the matching application and MCP versions.

[Artifact editing](../src/domain/resume/artifact.service.ts) checks `expectedRevision` and the output lease. [Manual content](../src/domain/resume/resume.validation.ts) accepts user-written display text for dates, links and statements, including empty statements. It checks object shapes, field types, IDs and size bounds. Manual additions and rewrites clear their evidence links, while unchanged statements retain them. Output commits are fenced by the attempt token and content revision. [Runtime leases](../src/platform/database/runtime-leases.ts) prevent concurrent builds and fence expired workers.

[Output](../src/platform/resume-output/exporter.ts) embeds the pinned, licensed [Noto font](../resources/fonts/version.json), preserves link display text, makes valid HTTP(S) links clickable, compiles escaped self-contained HTML, lays out A4 pages in an isolated Electron world after fonts load, and prints that same HTML to PDF. Entries/bullets prefer intact boundaries; long text splits across pages without shrinking/cropping. [File writes](../src/platform/resume-output/files.ts) use private temporary files, atomic replacement and relative HTML/PDF records under `userData/artifacts/`. Output state is independent; interrupted/missing output can be rebuilt without a model call. DOCX is unimplemented. Hard deletion preserves snapshots/generated output; it is not a privacy purge. Historical references carry `ACTIVE / DELETED` from deletion audit.

| Deleted object | Result |
| --- | --- |
| Job | Remove sources/events; retain generation runs and artifacts |
| Profile | Remove all items/facts; retain generation history |
| ProfileItem | Remove its descendant subtree and attached facts |
| Fact | Remove source fact; retain historical artifact links |
| GenerationRun | Remove its Artifact, Fact links, rewrite receipts and linked Resume Trace |
| Artifact | Remove its links; retain the run |

`generation_runs.job_id` and `artifact_facts.fact_id` are stable logical references so historical sources can disappear. Snapshot IDs are also logical references. All other ownership relationships use foreign keys. Audit survives every business deletion; no audit-clear or disk-file-cleanup API is implemented.

## 4. Audit and transactions

[Operation receipts](../src/platform/database/operation-receipts.ts) use (operation, request_id), normalized input hash, logical target, first result JSON and creation time. job.import/application.add_note/application.schedule_event and all profile writes record the receipt inside the same Domain transaction as business rows and success audit. Identical retries return the first result across processes/restarts; changed payload or a deleted target conflicts. Receipt result snapshots are retained after target deletion; deletion is not a privacy purge. No automatic recreation or nested service transaction occurs. Resume start keeps its separate same-runtime receipt/lease rule.

[Transactions](../src/platform/database/transactions.ts) and [database triggers](../src/platform/database/migrations/audit-triggers.ts) automatically append audit for every changed business row. Callers supply business parameters only. A write operation owns one internal transaction: all mutations and success audit commit together, or all roll back. Multi-row operations share a request and transaction ID. Ordinary business/audit queries remain read-only; explicit capability reads add access audit below.

| Element | SQL fields | Allowed contents |
| --- | --- | --- |
| What | `event_type`, `action` | Fixed operation name; `CREATE / UPDATE / DELETE` |
| When | `timestamp` | Backend-generated UTC time |
| Where | `component`, `location` | Logical component/operation identifiers |
| Source | `source`, `request_id` | Trusted entry category and generated request UUID |
| Outcome | `status`, `error` | `SUCCESS / FAILURE`; error code only |
| Identity | `actor_id`, `target_type`, `target_id` | Opaque subject and business object identifiers |

Additional fields are `id`, monotonically increasing `sequence` and `transaction_id`. ArtifactFact targets encode their three opaque key IDs as a JSON array string. USER, AI, SYSTEM and EXTERNAL use fixed local identifiers; source is `RENDERER / GENERATOR / STARTUP / AI_CLIENT / MCP_SERVER`. This is a local single-user identity scheme, not multi-user authentication. Public DTO fields use camelCase.

No before/after values, arbitrary metadata, business bodies, prompts, credentials, raw exception messages, stack traces, physical paths or page URLs are retained in audit. An SQL authorizer and triggers reject audit updates/deletions and forged inserts. Business writes without the internal context are rejected. Successful no-op operations with no changed rows create no success record; a generation gate rejection is a successful persistence operation whose run state becomes FAILED.

Failed writes first roll back, then append one failure audit in a separate transaction. The failure retains its request ID; its transaction ID belongs to the failure-audit transaction. A validated target ID is included when known, otherwise null. Invalid business write input is audited without copying input. If failure audit cannot persist, return `AUDIT_UNAVAILABLE`; do not claim it was recorded. Untrusted/unknown IPC requests are rejected before business execution. Settings/secrets use separate file adapters and never place credentials in SQLite or audit.

**Implemented AI call audit:** the Main-internal `recordAI` capability in [Transactions](../src/platform/database/transactions.ts) writes `AI_STREAM_START`, `CREATE`, component `ai`, location `chat.stream`, source `AI_CLIENT` and actor `local-user`. `targetType = ai_request`; target/request IDs are the same generated opaque request UUID, with no business-object mapping. Time, record ID and transaction ID are database-layer generated. [Audit queries](../src/platform/database/audit-reader.ts) accept this logical target without treating it as a business entity/table.

Each accepted request attempts one audit: the first valid SSE chunk commits `SUCCESS` before content is forwarded; startup failure/cancellation commits `FAILURE` with a fixed code. Success means the stream started, not that output completed. Post-start completion, failure and cancellation add no call audit. A manual retry creates a new request. Audit failure stops forwarding/aborts the request and reports `AUDIT_UNAVAILABLE`; the external call may already have occurred. No provider/model/URL, usage, duration, message, prompt, output, business snapshot or extra metadata is persisted. This legacy API remains for connection tests/imports; Ask AI uses the transcript storage below.

**Agent model audit:** every complete or streaming call records one fixed AGENT_MODEL_RESULT outcome through recordAgentModel, with component ai, location agent.model, source GENERATOR and a Main-bound internal Agent label. Only opaque request IDs and fixed outcomes are stored; prompts, outputs, secrets and hidden reasoning are excluded. Audit failure terminates execution.

**Implemented audit browsing:** the read-only [Settings viewer](../src/pages/settings/AuditViewerSection.tsx) uses `audit.list` without schema/IPC changes. It defaults to 25 records per page, ordered by descending sequence. Type/status, exact target/request/transaction IDs and inclusive time boundaries compose existing filters. [Filter conversion](../src/pages/settings/audit-filters.ts) validates IDs/ranges and converts local datetime inputs to canonical UTC; details show localized time plus its stored UTC value. Refresh/reset/filter application restart at page one. Pages use offset pagination; new writes can shift subsequent pages, so refresh to see the latest ordering. No export, automatic polling, log mutation or business-content reconstruction is provided. Settings/key writes remain outside audit; AI success retains its startup-only meaning.

**Implemented capability audit:** [read/write wrappers](../src/platform/tools/capabilities.ts) validate arguments and commit `START` before invoking a Domain service or MCP Client, then commit one `END` with success/fixed error and elapsed time. Tool bindings do not write audit. Native writes reuse the existing business transaction, producing one business change audit per changed row plus a distinct capability access/outcome pair; external network waits never hold a SQLite transaction.

The [controlled-runtime sink](../src/platform/database/capability-audit.ts) writes the append-only `capability_audit` table: invocation ID, phase, UTC timestamp, runtime-bound Agent/run IDs, approved tool name/mode, optional Server/original name, validated native target type/UUID, duration, status and error. It stores no input, output, prompt, URL, command, credential or raw exception. Arguments rejected before execution create no access record. SQL guards and the authorizer reject forged inserts, updates and deletions.

Start-audit failure prevents execution. End-audit failure reports `TOOL_AUDIT_UNAVAILABLE` without retry or rollback claims; an external or committed local write may already have happened. Only unmatched starts owned by dead instances receive an `INTERRUPTED` end; live calls are preserved. The existing `audit.list`/Settings viewer still reads only business/AI `audit_logs`; capability diagnostics remain runtime-internal. [Tests](../tests/capability-audit.test.ts) cover privacy, failure, rollback and immutable records; [MCP architecture](mcp-architecture.md) owns execution policies/lifecycle.

### Ask AI transcript storage

[Unified Agent storage](../src/platform/database/repositories/chats.ts) saves ordered items, request receipts and diagnostics for both definitions. Ask Runs reference a Session and share its sequence and checkpoints. Isolated Resume Runs have a null Session and order items within the Run. Chat admission still permits one admitted Run per Session. Deletion cascades the private records. Smart Paste source markers preserve history and disable generic retry.

Only the [Main recorder](../src/platform/electron/agent-recorder.ts) appends model/tool Items. It saves returned readable reasoning with source/type, encrypted-block markers, tool call IDs, full arguments/results, fixed errors and durations. [Transcript redaction](../src/platform/electron/transcript-redaction.ts) removes credential fields before persistence/events; ordinary business text remains complete. System prompts, encrypted payloads, signatures and raw exceptions never enter Items. Transcript content is separate from content-free audit. Item skeletons precede events; text uses one-second checkpoints and final writes, not per-token SQLite updates. A crash may lose text since the last checkpoint. Tool Items also store allowlisted Guard counters, reasons, execution markers, confirmed archive effects and optional warning/recovery level with fixed nextAction, without credentials or evidence fingerprints; diagnostics cascade with chat deletion and never restore Guard execution state. The [detail view](../src/app/components/AgentTimelineItem.tsx) displays them. Existing JSON storage needs no migration; historical snapshots may omit the new fields. Calls skipped before dispatch create no tool Item or uncertain write.

Provider continuation capsules are separate from ordinary chat projection IPC and contain validated assistant messages including signatures/encrypted reasoning; they cascade on chat deletion. History reconstructs assistant/tool exchanges without replaying tools, omits continuation metadata after a provider/model switch, and excludes it from compaction prompts. Existing Items remain readable; absent historical details are not reconstructed.

**Implemented request diagnostics:** [Migration 14](../src/platform/database/migrations/chat-model-requests.ts) introduced request diagnostics keyed by Run/ordinal, cascading with chat deletion. The [request observer](../src/platform/agent/pi/request-observer.ts) records preparation time, Provider/model, agent-turn/context-summary purpose, loadout version, expected/Pi/provider name mappings, canonical SHA-256 input-schema fingerprints, verification and activation-repeat outcomes through Main; persistence failure prevents dispatch. Prepared does not mean sent or successful. [chats.listModelRequests](../src/platform/electron/data-contract.ts) paginates these records; they never enter model history, transcript Items or audit and contain no bodies, full schemas, arguments, results or reasoning. Existing chats.deleteSession removes them only after all Runs settle, preserving business data and audit. [Tests](../tests/chat-model-requests.test.ts) cover migration, persistence, pagination and deletion; the request-schema diagnostic UI remains planned.

Run ownership uses runtime_instances. Recovery interrupts only dead/expired owners; live MCP startup cannot interrupt Main work. Partial answers survive and unfinished tools remain uncertain. New input creates a new Run; old business writes never replay. [Context checkpoints](../src/platform/database/repositories/ask-context.ts) save versioned summaries, monotonic compacted user-turn boundaries and minimal resource/outcome references. The token-driven model view preserves complete turns and labels partial answers; raw transcripts remain intact. [Migrations 16 and 17](../src/platform/database/migrations/chat-react-cycles.ts) persist Cycles keyed by `(run_id, cycle_index)` and enforce one open Cycle, contiguous indexes and immutable settled records. Model request ordinals and tool IDs are saved with diagnostics and responses before the respective dispatches. Terminal settlement commits the Cycle, Run and transcript together. Historical Runs stay empty and recovery preserves the last recorded Cycle.

[Ask IPC](../src/platform/electron/ask-agent-contract.ts) exposes start/cancel/getRun/listActive/onEvent with trusted-frame and window ownership checks. Manual Chat CRUD uses typed data IPC; Renderer cannot fabricate Runs or output Items. Retry creates a new Run, while a run that attempted writes requires state review rather than automatic replay. [Tests](../tests/chat.test.ts) cover constraints/recovery and [projection tests](../tests/ask-store.test.ts) cover snapshot races/gaps. [Migration 13](../src/platform/database/migrations/ask-serial.ts) preserves historical Memory progress for export and retires its execution lifecycle.

### Copy Debug JSON

**Implemented:** `data.chats.copyDebugJson({ sessionId })` resolves to `Result<null, ErrorCode>` through the existing allowlisted [Data Bridge](../src/platform/electron/preload/data-bridge.ts), trusted `DATA_CALL` handler and backend dispatcher. The independent [Domain use case](../src/domain/chat/chat-debug.service.ts) validates input before reading; a missing optional host output returns `NOT_IMPLEMENTED` without reading.

The [repository](../src/platform/database/repositories/chat-debug-export.ts) reads all eight chat tables for that Session in one explicit snapshot transaction, without pagination/truncation. Runs sort by `created_at,id`; Items by `sequence`; requests/responses by `ordinal`; Memory Progress by `sequence,message_id`, ascending. Raw column names, IDs, numeric flags, nulls and `*_json` strings remain unchanged; absent checkpoint is `null`, collections are `[]`. Running/Pending and terminal Runs include persisted records only: no stream flush, recovery, MCP, business/audit writes, reconstruction or additional redaction.

The [v2 schema](../src/domain/chat/chat-debug.v2.schema.json) adds `cycles` ordered by `cycle_index` and the latest `cycleStatus` to each Run entry. With zero Cycles these are `[]` and `null`. The [v1 schema](../src/domain/chat/chat-debug.v1.schema.json) describes earlier exports. Readers select a schema by `schemaVersion`. [Main output](../src/platform/electron/main/chat-debug-output.ts) awaits clipboard write and exact readback. The export carries the Electron version, platform and nullable build-time commit. Renderer receives success/null or a fixed error. The sharing warning covers private transcript and Provider data. See [export tests](../tests/chat-debug-export.test.ts) and [Electron smoke](../scripts/chat-debug-smoke.cjs).

## 5. API contract and access

The sandboxed [Preload](../src/platform/electron/preload/index.ts) exposes `window.data`. The complete typed inputs/outputs live in [DataContract](../src/platform/electron/data-contract.ts); field/enumeration definitions remain in the linked Domain types. [Main IPC](../src/platform/electron/main/data-ipc.ts) requires an owned window, its top frame and the exact trusted renderer document. External pages/subframes cannot access data.

Every method accepts one input object and resolves to `{ ok: true, value }` or `{ ok: false, error }`. Implemented business endpoints reject unknown fields, including injected audit/transaction fields. Edit-details methods replace the allowed details, applying documented type defaults; they are not arbitrary patches. Lists use `limit` (default 25, maximum 100) and `offset` (default 0, maximum 1000000), returning `{ items, total }` with stable ordering. Multi-table reads use a consistent read transaction.

| Namespace | Implemented responsibility; exact signatures are owned by [DataContract](../src/platform/electron/data-contract.ts) |
| --- | --- |
| `jobs` | Job/company CRUD, source attachment, archive and paginated queries |
| `profiles` | Contact/item/fact CRUD and explicit reviewed import |
| `applications` | Legal status changes, notes, schedules, event/calendar queries |
| `resumes` | Manual Run/Artifact CRUD and provenance queries; Agent stages use MCP |
| `chats` | Session CRUD, paginated Items/Runs/diagnostics and confirmed Main-only debug clipboard copying |
| `audit` | Read-only content-free audit browsing |
| `settings`, `secrets` | Validated file preferences and key status/save/delete; never return keys |

The API offers no raw SQL/table CRUD, unrestricted filters, transaction management, audit writer or generation-stage writes. Agent generation stages use MCP, separate from this manual/UI IPC API. IPC mutations are not automatically retried/idempotent; refresh uncertain state before retrying. MCP creation receipts provide the explicit exceptions described in section 4. The source contract below owns the fixed errors.

[Fixed error codes](../src/domain/common/errors.ts) cover invalid input, missing/conflicting state, storage/audit availability, forbidden callers, encryption and AI failures. Only codes cross IPC; raw database messages never do.

[Profile import IPC](../src/platform/electron/profile-import-contract.ts) exposes selection, start, retry, cancellation and discard. Parse retry retains the session ID, creates a new task ID and reuses extracted text.

The separate [AI API](../src/shared/ai.ts) retains non-Agent streaming tasks. [Resume IPC](../src/platform/electron/resume-contract.ts) exposes `window.resume.start/getTask/cancel/retryOutput/getPreview/exportPdf/onEvent`; events carry run ID and monotonic sequence, never hidden reasoning. Each window permits one active task; navigation preserves it, window disposal cancels it. Before publication cancel terminates the run; afterward it stops output only. Export opens a system save dialog and copies the existing PDF; `PDF_EXPORT_FAILED` leaves that application copy ready for another save attempt.

[Job import IPC](../src/platform/electron/job-import-contract.ts) retains the task ID on retry and parses the cached source again. Both bridges enforce window ownership.

## 6. Settings, secrets and remaining work

Controlled runtimes share `database.sqlite`, its auxiliary files and `userData/artifacts/`. Main owns `userData/settings.json` and `userData/secrets.enc`; the MCP Server does not load application credentials. Electron Session separately owns website cookies/storage. Ordinary business audit cannot be disabled.

The optional Main-only [MCP config](../src/platform/storage/mcp-config.ts) reads version-1 `userData/mcp.json` without creating/resetting it. Configuration contains reviewed stdio executable/arguments and tool manifests; it accepts no environment/credential fields and is excluded from Renderer preferences. MCP credentials/OAuth are planned; do not put secrets in command arguments. The [MCP document](mcp-architecture.md#3-first-party-and-third-party-clients) owns configuration examples and limits.

[Preferences](../src/platform/storage/preferences.ts) validate version 1, English/Simplified Chinese, a `light / dark / system` theme and optional Gmail/Outlook/custom HTTPS webmail without embedded credentials. Existing version-1 light files remain compatible; the version stays 1. Light remains the default. Store the preference (including `system`), not its resolved color scheme; unrelated partial saves preserve it. Apply saved preferences only after successful atomic replacement. Missing files use defaults without writing. Partial saves merge the latest file; malformed/future files fail without resetting. [Atomic replacement](../src/platform/storage/files.ts) uses a private temporary file and rename; failed writes preserve previous data. Smart Paste stores each configuration ID, title and prompt. Missing settings use the localized default and an explicit empty list stays empty.

[AI preferences](../src/platform/storage/ai-preferences.ts) validate up to 20 named providers, HTTPS endpoints with loopback HTTP allowed, explicit key requirements, up to 100 model IDs per provider and an optional global default. Endpoints accept path prefixes and reject credentials, queries and fragments. The retired `parallelModels` field is ignored on read and dropped on the next save. Missing AI and timeout settings use defaults. Provider removal requires deleting its key first.

[Timeout settings](../src/shared/ai.ts) store global `ai.timeouts.requestSeconds`, `pageSeconds` and `modelsSeconds`, defaulting to 120, 20 and 15 seconds. Each is an integer from 1 to 3600; invalid writes preserve the previous file. AI limits cover chat, job/profile parsing and each Resume Agent call; page reading and model detection have independent limits. Provider edits/removal and unrelated preference saves preserve these values. [Settings tests](../tests/settings.test.ts) verify legacy reads, persistence and atomic rejection.

[Secrets](../src/platform/storage/secrets.ts) store version-2 ciphertext maps keyed by Provider instance ID, encrypted by Electron `safeStorage` at [Main composition](../src/platform/electron/main/index.ts). Unavailable encryption (including Linux `basic_text`) refuses saves; deletion remains available. The API returns configuration/encryption status, never decrypted keys. Keys stay outside ordinary preferences, SQLite, snapshots and audit; file preferences/key operations do not append business audit. Version-1 OpenAI ciphertext remains readable and upgrades atomically on the next key write without decrypting unrelated keys. Only the internal AI service can read plaintext through the injected capability; the public bridge returns status. Saving configuration/keys makes no model request; the explicit connection test sends a short prompt to the saved provider/model and can incur charges.

[Settings tests](../tests/settings.test.ts) verify reopen, all theme values, version-1 compatibility, partial-save preservation, validation, corruption, write failures and encrypted-key lifecycle. [Fallback adapters](../src/platform/storage/index.ts) return `NOT_IMPLEMENTED` for missing file services; debug copying separately requires its host output. AI chat uses local fixtures in [AI tests](../tests/ai.test.ts) and [production smoke](../scripts/ai-smoke.cjs); live third-party compatibility and account permissions remain unverified. Strict structured-output negotiation, authenticated page extraction/deduplication, remaining business UI and full privacy purge remain unimplemented. Resume provider compatibility is verified by local fixtures; live providers remain unverified.

## Smart Note storage and Memory v1

**Implemented:** canonical Markdown lives in `userData/smart-note/knowledge/` and `memory/`, sharing one `.git`; no Note/Memory business table exists. Job, Profile and Fact remain authoritative business facts. Independent `knowledge-index.sqlite` and `memory-index.sqlite` caches keep FTS, vectors, ranking and context expansion isolated; [embedding identity](../src/platform/knowledge/rag/embedding-protocol.ts) controls vector compatibility.

[Migration](../src/platform/knowledge/workspace-storage.ts) completes the old restore journal, locks the legacy library and workspace, hashes/copies every regular file (including untracked data and `.git`) to same-filesystem staging, and commits the directory change. It verifies contents/history before atomic publication, retains `knowledge-archive-v1`, and replaces the old entry with a file that old path checks reject. Links, unsafe names and unverifiable states stop migration; journals make interrupted stages reentrant without initializing an empty library.

`smart-note-runtime/` remains outside Git and stores migration/restore journals, generation 1, original HEAD, migration commit, explicit legacy commit IDs and normalized-remote consent. Legacy commits map entirely to Knowledge, including old directories named `knowledge/` or `memory/`; current layout is never inferred from prefixes alone. Independent MCP requires Main to finish initialization/recovery first.

[Backup](../src/platform/knowledge/git/backup.ts) snapshots Markdown in both spaces under one lock, follows the active local branch and syncs to the configured remote branch. Space-filtered history paginates after filtering and returns relative paths; restore checks only the target tree revision, snapshots both spaces and journals only target changes. Internal sync uses workspace journals; the UI exposes no workspace restore. Root rename/delete is invalid; `expectedRevision:null` creates only, updates require the current SHA-256. Git omits empty directories and retains deleted-note history.

[Workspace](../src/platform/knowledge/workspace.ts) persists sync consent through trusted IPC for the current normalized remote. Upgrade, first remote use and remote changes require disclosure that Memory and its Git history upload too. Without consent sync performs local backup only; the transport gate also covers conflict uploads. Unknown remote layout cannot replace local files. Audit migration 10 preserves existing rows and adds opaque Memory targets; permissions belong to [MCP architecture](mcp-architecture.md).

[User model storage](../src/platform/models/paths.ts) is independent of Smart Note, its two derived indexes and `database.sqlite`: macOS `~/Library/Application Support/JAB/managed-models`, Windows `%LOCALAPPDATA%/JAB/Models`, Linux `${XDG_DATA_HOME:-~/.local/share}/JAB/models`. `JAB_MODEL_STORE` accepts an absolute override. Verified revisions, retry staging, heartbeat locks/leases and `.installed.json` are filesystem resources; activation rechecks size/SHA256. Atomic `seed-preferences.json` records initialized revisions and disables automatic Seed import after removal. npm update/uninstall preserves these files; unavailable weights retain chunks/FTS/vectors but retrieval falls back to lexical search. [Preference loading](../src/platform/storage/knowledge-preferences.ts) drops obsolete providerId/modelId only on disk reads and preserves semanticEnabled, default true.
